宝玉 @dotey

  • DeepInfer 到底开源了什么：他把推理框架比作后厨出餐系统，模型只是菜谱，调度好了同样的卡能多接几倍单，核心提速靠投机解码，草稿模型先猜最多 5 个 token 再由大模型一次核对。门槛很高，只支持 V4.1 Flash，要 Blackwell 或昇腾 950 这类数据中心卡，开源的只是离线推理，缓存系统和分离式部署都没放出来 原帖
  • deepseek-recipe 的用处：配套组件负责把 OpenAI 和 Anthropic 的请求格式翻译成 DeepSeek 能读的输入，再把思考过程和工具调用翻回去，对齐官方 API 行为，MIT 协议，有 Python 和 Rust 版 原帖
  • GPUI 换回 Electron 的理由：他做 baocut 时踩了 GPUI 的坑，Rust 编译吃 CPU 吃磁盘，改一点 UI 要等几分钟到十几分钟，agent 验证 UI 也慢。换回 Electron 后能热更新，还能直接在 agent 内置浏览器里验证，重渲染部分用 Rust 编成 wasm 补性能 原帖

看法：今天讲 DeepInfer 最清楚的一篇，GPUI 那条是真踩过坑的一手经验，"对 agent 友好" 正在变成技术选型的新标准

岚叔 @LufzzLiz

  • DeepInfer 的硬数据：官方披露单集群每天服务 155 万亿 token，按低谷价算每 GPU 小时营收 38 美元，注意这是营收不是利润。长上下文靠约 100 PiB SSD 存 KV 缓存，Agent 流量留 3 天，聊天流量留 7 天，最小高效部署单元建议 64 张 Prefill 卡加 64 张 Decode 卡 原帖
  • MiniMax M3.1 Flash 实测：拿鹈鹕单板滑雪和 DeepSeek V4.1 Flash 对比，MiniMax 更贴题，DeepSeek 视觉更好但做成了空中漂移，他的结论是 MiniMax 任务还原度更高，属于听话好用型 原帖

看法：数字整理得扎实，模型对比也是自己跑的，比单纯转述官宣强很多
